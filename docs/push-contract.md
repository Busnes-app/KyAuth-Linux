# KyAuth-Linux ↔ KyIdentity push contract

The wire contract KyAuth-Linux depends on. The Android contract (pairing, push v2 binding,
push-token v2 refresh, `/api/mfa/push/respond`) is unchanged. This file records only what
Linux adds. Server side: KyIdentity `feat/linux-authenticator`.

## Registration

`POST /api/notifications/native/register`, same body as Android, with:

- `platform: "linux"`.
- No `attestation`. The device is graded `none`.
- `publicKey`: standard base64 of the P-256 SubjectPublicKeyInfo DER.
- `pushTransport`: `"unifiedpush"` (Nura / postmarketOS) or `"ubuntupush"` (Ubuntu Touch).
- `pushP256dh`, `pushAuth`: required for both transports. base64url without padding, a 65-byte
  uncompressed P-256 point and 16 random bytes, generated by the app.
- `pushToken`:
  - `unifiedpush`: the endpoint URL the distributor returned.
  - `ubuntupush`: the token from the Lomiri `PushClient`, 1–512 bytes of
    `[A-Za-z0-9+/=_.:-]`.

A `linux` device may use only `unifiedpush` or `ubuntupush`. `fcm` is refused.

## Delivery

Both transports carry the same plaintext: the flat all-string JSON object Android receives
(`type`, `title`, `body`, `challengeId`, `deviceId`, `deviceUserId`, `purpose`,
`expiresAtEpochMs`, `devicePlatform`). Both encrypt it with RFC 8291 `aes128gcm` to the device's
`pushP256dh`/`pushAuth`. No plaintext path exists.

- `unifiedpush`: WebPush POST to the endpoint, as on the existing branch.
- `ubuntupush`: `POST <KYIDENTITY_UBUNTU_PUSH_URL>` (default `https://push.ubports.com/notify`,
  https only, through the guarded client) with:

  ```json
  {
    "appid": "<KYIDENTITY_UBUNTU_PUSH_APPID, default kyauth.busnes_kyauth>",
    "token": "<pushToken>",
    "expire_on": "<challenge expiry, RFC 3339 UTC>",
    "replace_tag": "kyauth-mfa",
    "data": {
      "message": { "kyauth": "<base64url, no padding, of the aes128gcm body>" },
      "notification": {
        "tag": "kyauth-mfa",
        "card": { "summary": "Sign-in request", "body": "Open KyAuth to approve or deny.",
                  "popup": true, "persist": true },
        "vibrate": true, "sound": true
      }
    }
  }
  ```

  `replace_tag` makes a newer request replace a pending one, so ignored requests cannot reach
  the service's pending limit. The serialized `data` stays at or under 4096 bytes (the UBports
  `MaxUnicastPayload`). The notification text is fixed and carries no user, server or challenge details. The `appid` is
  server configuration, never device input. UBports sees only ciphertext, the token and the
  timing.
